# `footnote code-index --deep`: default tier vs deep tier on six projects (20 November 2026)

What was built (#299): `--deep` checks that the project's compiler indexer is installed, says the exact install command when it is
not, and asks before running it (`--yes` for scripts, `--no-install` or no terminal = report only). Every indexer run, deep or not,
now has a timeout (30 min, `FOOTNOTE_CODE_INDEXER_TIMEOUT_SECS`), capped stdout and stderr, and an index over 512 MiB is refused.

**Finding that changes the premise:** the compiler graph was already what `code-index` builds whenever the indexer is on PATH
(CODE-TIERS section 3). "Default tier" below therefore means the parser-only graph (no indexer on PATH, the graph a machine
without the indexers gets); "deep tier" is the graph with the indexer present. `--deep` makes the second one reachable on purpose.

## Method

Same scorer as CODE-TIERS (`score_tiers.py`, same classes, same recall denominator). Fixtures: shallow clones, nothing installed
in them, so no project code ran. click 08b803c, httpx 7cff5f7, rich 3a109cc and zustand 9fed2eb are the commits of #216; hono is
75ff8e3 and nest e0600bb (the pinned a8ae5b1 and bbbfaf1 were not re-fetched), so those two rows are not comparable with older
tables, only with each other. Indexers were already installed globally on this machine (scip-typescript 0.6.2 Apache-2.0,
scip-python 0.6.8 MIT); nothing was installed for the bench. Machine: Windows 11, release build, one run per cell.

- default: `code-index` with only System32 and git on PATH, links written with `FOOTNOTE_CODE_RULES`.
- deep: `code-index --deep --no-install` with the indexers on PATH; its refs table dumped to the same tsv format (`deep_prep.py`).
- truth: a second, separate `code-index` run on the same sources.

## Results

| Scope | Tier | Links | Analyzed precision | Recall |
|---|---|---:|---:|---:|
| Python | default | 9298 | 0.864 | 0.460 |
| Python | deep | 44636 | 1.000 | 1.000 |
| TypeScript | default | 8262 | 0.937 | 0.608 |
| TypeScript | deep | 71201 | 1.000 | 1.000 |

By project (default / deep): click 0.595 / 0.359 vs 1.000 / 1.000; httpx 0.604 / 0.224; rich 0.999 / 0.600; hono 0.913 / 0.278;
nest 0.962 / 0.777; zustand 0.943 / 0.578 (precision / recall for default).

**How to read the deep rows: they are 1.000 by construction, not a finding.** The truth is the compiler graph, and the deep tier
is the compiler graph; two runs of the same indexer on unchanged sources agree on every link. What the numbers do show: the deep
graph is reproducible on these sources. The deep link counts are larger because
they count every compiler reference (constructors, accessors, types), while the default counts calls only, so link counts across
the two rows are not a recall comparison. The recall gain of deep over default is the default's miss: 0.54 Python and 0.39
TypeScript of the compiler's function edges.

Time (wall clock including start-up, one run): default / deep, in ms: click 494 / 6273, httpx 411 / 4790, rich 653 / 12191,
hono 1454 / 6453, nest 3231 / 6202, zustand 432 / 1783. Deep costs 2 to 19 times the parser, and runs the type checker over the
project (it executes no project code; Rust is different, `rust-analyzer scip` runs build scripts).

## Not measured

Rust, Java (scip-java via `FOOTNOTE_CODE_SCIP`), Windows Store python3 on a machine without any real interpreter, and the
interactive install on a machine that lacks the indexers (covered by tests with a stand-in installer, not run for real: the bench
did not uninstall anything).
