## 3. Architecture effectivement en place

Le produit est majoritairement en Rust. Il n'est pas encore entièrement autonome vis-à-vis de Python.

- SQLite conserve les données de référence ; Tantivy fournit l'index lexical dérivé.
- Le profil livré utilise `bekko-a8m` et `gte-small`, des vecteurs stockés en int8 et une fusion par combinaison convexe, avec alpha 0,55.
- Le chemin dense Rust effectue un scan exact jusqu'à 50 000 entrées stockées. Au-delà, il utilise une présélection lexicale de 1 000 candidats.
- L'encodage passe par un **worker Python résident**, lancé depuis [src/semantic.rs](../src/semantic.rs). Le chargement du modèle n'est donc pas répété à chaque requête chaude.
- [tools/embed.py](../tools/embed.py) importe NumPy, ONNX Runtime et tokenizers. Il prépare les tenseurs, appelle le moteur ONNX, puis réalise pooling et normalisation.
- Le helper de production accepte actuellement une recette de pooling précise et des vecteurs de dimension 384. Ajouter un modèle du laboratoire ne se réduit pas nécessairement à changer son nom.

Le laboratoire Python est distinct du produit. Il permet des recettes et configurations plus nombreuses, pré-encode les requêtes pour certains essais et utilise d'autres réglages de threads. Les timings de composants, d'encodage et de recherche complète ne sont pas interchangeables.

## 8. Python, NumPy, Rust et pistes d'optimisation

La question est de réduire un coût mesuré, pas de choisir un langage ou une bibliothèque pour sa nouveauté.

- NumPy réalise les calculs de tableaux, pooling et normalisation. Le laboratoire utilise déjà OpenBLAS. Le cœur Rust réalise ses propres calculs de recherche ; il ne faut pas attribuer tous les timings du produit à NumPy.
- Polars vise surtout les corpus et tableaux de résultats : lectures, filtres, jointures et agrégations. Il peut compléter NumPy ; il ne remplace pas directement ses tenseurs.
- Numba peut compiler et fusionner des boucles numériques. NumExpr est une piste pour de grandes expressions élémentaires. NumKong, anciennement SimSIMD, fournit des calculs vectoriels spécialisés. Leurs gains locaux ne sont pas encore mesurés.
- JAX est une piste secondaire pour des calculs répétés qui amortissent compilation et transferts. Ne pas supposer que les options GPU sont compatibles avec le poste.
- OpenVINO CPU est une piste concrète à comparer au moteur ONNX Runtime actuel sur le CPU Intel.
- Un encodeur Rust `ort` + `tokenizers`, ou FastEmbed-rs si les recettes sont compatibles, pourrait retirer le worker Python du produit. Le laboratoire peut rester en Python. Un port Rust ne garantit pas une accélération du même moteur ONNX natif.

Machine vérifiée : Intel Core Ultra 7 270K Plus, 24 cœurs/logiques ; AMD Radeon RX 6800.
