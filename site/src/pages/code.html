Who calls this function? Not a guess.

Answered from the compiler's own index.

Code reads the index your language tools already build and links a symbol to its callers and callees. It would rather show no caller than a wrong one.

Current scope

All commands below ship in the default source build today (CLI, MCP tool footnote_code, and the Launcher Code map). Cross-product links from a symbol to Library docs and Memory fixes are still maturing, Java and parser-only tiers have smaller benchmark sets, and a standalone installer is not released yet.

How it works

Footnote uses rust-analyzer for Rust, scip-typescript for TypeScript and JavaScript and scip-python for Python. Agents get the same answers through the footnote_code tool; files changed since indexing come back marked stale.

  • footnote code-index . builds the graph of the project in the current folder, in seconds. Rebuild after big changes.
  • footnote code lookup shows the symbol lookup: signature, file and lines, callers with call-site lines, and callees.
  • footnote code-map draws the architecture: folders as blocks, links between them, outside packages used.
  • footnote code-impact <name> lists, before a change, the callers up to 3 levels, the tests reached, and the files and memories affected.

Against other tools: one repository

On one Rust repository, 37 files without tests, one run: Footnote has fewer wrong links and slightly lower recall than CodeGraph. It is the repository our rules were tuned on, so read this as a data point, not a ranking.

Not here yet

  • A symbol linked to its Library docs and the Memory fixes about it. A related field exists; we have not measured the links.
  • A map of a project's inputs and outputs.
  • We have not measured whether reading the graph first saves tokens. We make no claim about cost.

For Rust, rust-analyzer builds the project, which runs its build scripts and procedural macros. Index only code you trust. scip-typescript and scip-python only read the code.
