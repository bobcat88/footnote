What is saved, and when it comes back

  • Saved by your agent. Preferences, decisions, fixes and sessions. The agent writes them itself, in its own session. No second model reads your conversation.
  • At session start Footnote adds your preferences and the project's memories.
  • On each prompt it adds the memories that match the prompt.
  • Every 10 prompts, at the end of a turn, it asks the agent once to save what it learned. /remember does the same on demand.
  • Agents. Memory hooks work with Claude Code, Codex, Grok and DeepSeek Harness. Search over your documents works in any MCP host, Gemini CLI included.

See it, change it, delete it

Control is the reason to trust it, so it comes first. A global preference saved by an agent waits for your review before any agent sees it.

  • footnote memory-list lists what is stored.
  • footnote memory-review lists the memories worth a second look, and the preferences waiting for you. footnote memory-restore <id> approves one.
  • footnote forget <id> deletes one, or rejects a pending preference.
  • The Launcher shows recent memory activity and token use.

What stays on your machine

  • Memories live in one SQLite file. There is no telemetry.
  • Three commands you run use the network: footnote models install, footnote docs add and footnote crawl. Search and memory open no outbound connection.
  • An encrypted store exists, but it is experimental and Windows only.
  • The memories an agent receives are in its prompt, so the agent's own transcripts keep them in plain text. Encryption protects Footnote's store, not what agents write down.

Start

Turn on Memory.

You need Footnote installed first: see install. The command backs up each settings file it edits and leaves your existing entries alone.

Turn on

Registers Memory, its hooks and /remember in every supported agent found.

footnote install --memory

Turn off

Removes the hooks and MCP server. Your memories and settings are kept.

footnote uninstall --memory
